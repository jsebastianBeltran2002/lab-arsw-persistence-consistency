## Justificación de la distribución
La distribución inicial nos parece adecuada y la mantenemos, porque cada motor responde a una garantía distinta.

PostgreSQL se usa para los permisos porque el dato es una relación entre usuario y tablero que necesita integridad referencial, unicidad y transacciones con rollback. En la evidencia SQL se ve que no se puede crear una membresía para un usuario que no existe, que no se pueden tener dos membresías para el mismo par y que una revocación revertida nunca se llega a ver. Por eso es la fuente oficial para autorizar.

MongoDB se usa para el contenido porque la consulta principal es leer o editar el tablero completo, y el documento junta lo que cambia al mismo tiempo: título, preferencias y versión. La atomicidad por documento de MongoDB alcanza para el control de versiones, porque la comparación y el incremento se hacen en la misma operación.

Redis se usa solo para datos efímeros o derivados como la presencia y la caché. Si se pierden no se rompe la corrección del sistema, por eso Redis corre sin persistencia y si se cae solo se degrada la presencia.

En un sistema real evaluaríamos mover el contenido a PostgreSQL con JSONB, porque permitiría validar la membresía y actualizar el tablero en una misma transacción y así cerrar la ventana entre validar el permiso y escribir. No lo hicimos porque el laboratorio no pide migrar y porque juntaría los dos servicios en un mismo esquema.

No guardamos los permisos solo en Redis porque en este entorno Redis no persiste y al reiniciarlo se borraría todo. Además no tiene llaves foráneas, unicidad declarada ni rollback, y una caché con TTL puede tener guardado un permiso que ya fue revocado.
